# Контекст

Контактная форма, запрос предложения и запрос образца должны направлять одинаково нормализованные обращения ответственному менеджеру. Интеграционная конфигурация может отсутствовать в review-среде и не должна попадать в браузер, логи или сообщения об ошибке.

# Решение

Все формы отправляют валидируемый server-side `Inquiry` через единый transport interface. Адаптер Telegram вызывается только при настроенной серверной конфигурации, экранирует содержимое и имеет ограниченное время ожидания; при отсутствии конфигурации возвращается typed temporary-unavailable state.

# Почему

Отклонены прямой вызов Telegram из браузера и отдельная реализация доставки для каждой формы: первый раскрывает интеграционные данные, второй приводит к несовместимой валидации и разным ошибочным состояниям.

# Последствия

UI сохраняет введённые данные, показывает доступный fallback и не заявляет об успехе без подтверждённой доставки. Транспорт можно заменить без изменения форм, а тесты обязаны мокировать внешнюю отправку и не создавать реальные обращения.
