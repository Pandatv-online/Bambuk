# Изначальная задача

> сверяется готовый результат. Всё, что сказано позже, дописывается

**Phase 4 — Implementation**
Phase 1–3 documentation is complete.
Read ALL of the following files before doing anything:
docs/reference-site-audit.md
docs/finland-site-architecture.md
docs/design-system.md
docs/component-inventory.md
docs/content-map.md
AGENTS.md
The reference-site materials under .firecrawl/ are also available for visual and structural reference.
**IMPORTANT**
Do not start by generating all pages.
First, inspect the repository and determine what implementation inputs are still missing.
The following information must NOT be invented:
Finnish company information
contact details
business ID / VAT information
manufacturer relationship wording
product prices
product availability
product specifications
installation prices
installation service area
delivery terms
sample policy
warranties
certifications
environmental claims
legal information
If something is missing, create a clearly marked placeholder and document it in:
docs/implementation-inputs.md
Do not silently invent content.
**Implementation strategy**
Build the website incrementally.
**Step 1 — Project foundation**
Set up:
Next.js
TypeScript
Tailwind CSS
Finnish /fi route structure
reusable layout
typography
design tokens
responsive breakpoints
image handling
SEO foundation
Do not introduce a different visual identity.
Follow docs/design-system.md.
**Step 2 — Global UI**
Implement the reusable global components first:
Header
Desktop navigation
Mobile navigation
Footer
Breadcrumbs
Buttons
CTA
Container
Section
Typography primitives
Product cards
Category cards
Image/gallery components
The components should be reusable rather than duplicated between pages.
**Step 3 — Homepage**
Implement the Finnish homepage according to:
docs/finland-site-architecture.md
and
docs/content-map.md
The homepage should be concise.
Prioritize:
Brand
Bamboo flooring
Product categories
Main benefits
Featured products
Installation service
References
CTA
Primary CTA:
**Pyydä tarjous**
Secondary actions may include:
Tutustu tuotteisiin
Pyydä näyte
Asennuspalvelu
Use the exact Finnish wording defined in the content documentation where available.
**Step 4 — Catalog**
Implement the catalog architecture.
The catalog must support:
categories
subcategories
product collections
product cards
filtering where specified by the architecture
breadcrumbs
pagination or appropriate loading strategy
Do not reproduce unnecessary complexity from the reference site.
**Step 5 — Product pages**
Create a reusable product page template.
Product information must come from structured data.
Do NOT hard-code individual product information into JSX.
The template must support different product categories with different specifications.
For example, an interior floor and an outdoor product may have different technical attributes.
Use typed flexible specifications.
**Step 6 — Commercial model**
The Finnish website is a distributor website.
Do NOT copy manufacturer prices.
Prices must be independently configurable.
For the first implementation, if prices are not yet supplied:
hide price;
show "Pyydä tarjous";
or use a clearly documented placeholder state.
Do not display fake prices.
The same applies to stock and availability.
**Step 7 — Installation**
Implement:
/fi/asennus
Installation is a primary service, not an informational footnote.
The page should contain:
introduction
process
what is included
preparation
service area
quotation CTA
Only use confirmed information.
Unknown information should remain a placeholder.
**Step 8 — Product information**
Implement the simplified information architecture from the documentation.
Do NOT recreate all 555 reference URLs.
Consolidate repetitive SEO content.
The website should contain only useful information that helps the customer:
understand bamboo;
choose a product;
understand technical properties;
understand installation;
understand maintenance; make a purchase decision.
**Step 9 — References / Gallery**
Implement a clean project/gallery section.
Prioritize visual presentation over long descriptions.
**Step 10 — Contact and quotation**
Implement:
contact page
quotation form
sample request flow where applicable
installation enquiry
Forms must be componentized.
Do not invent form endpoints.
If the destination is not configured, use a development-safe placeholder and document it.
**Step 11 — SEO**
Implement SEO for actual commercial pages.
Include:
metadata
canonical URLs
Open Graph
sitemap
robots.txt
semantic headings
product structured data where appropriate
Do NOT create SEO filler.
Do NOT generate hundreds of thin pages.
**Step 12 — Responsive implementation**
The site must work properly on:
mobile
tablet
desktop
Pay particular attention to:
header
navigation
product grids
product galleries
product specification tables
forms
CTA sections
Do not simply shrink the desktop layout.
**Visual QA**
Use the retained .firecrawl/ screenshots and captures as reference.
Compare the implementation against the reference design system.
Check:
spacing
typography
image proportions
card treatment
navigation
visual hierarchy
mobile behavior
The goal is:
**same brand language, simpler Finnish UX.**
Not:
**pixel-perfect reproduction of every legacy behavior.**
**Content QA**
Before considering a page complete, check:
Is the Finnish natural?
Is the content useful?
Is anything repeated?
Is there unnecessary SEO text?
Are claims supported?
Is manufacturer information separated from distributor information?
Are Lithuanian company details absent?
Are Lithuanian prices absent?
Is the Finnish CTA obvious?
**Definition of Done**
A phase is complete only when:
it follows AGENTS.md;
it follows the design system;
it uses reusable components;
it is responsive;
it contains no invented business facts;
it has no accidental Lithuanian company information;
it has no reference-site links exposed to visitors;
it passes TypeScript/build checks;
it has no obvious console errors;
the implementation is documented where necessary.
**Development order**
Implement in this order:
Foundation
Global components
Homepage
Catalog
Product template
Installation
Information pages
References
Contact/forms
SEO
Responsive QA
Final QA
Do not attempt to implement everything in one huge operation.
After completing each major stage, run the appropriate checks and fix problems before moving on.
Start with **Foundation + Global UI + Homepage**.
