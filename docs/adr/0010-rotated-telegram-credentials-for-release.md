# Контекст

Для доставки заявок выбран Telegram Bot API, но исходный токен уже был раскрыт в переписке. В review-среде интеграция должна оставаться проверяемой без реальных отправок и секретов в репозитории.

# Решение

Production-доставка включается только после ротации токена и ручной настройки новых server-only значений владельцем. При неполной конфигурации транспорт возвращает явное состояние временной недоступности без сетевого вызова.

# Почему

Рассматривались повторное использование раскрытого токена и его запись в пример окружения или тестовую фикстуру. Это сохраняло бы доступ к боту у любого обладателя старого значения и размножало бы секрет через историю репозитория; автоматическая проверочная отправка также создавала бы реальное обращение.

# Последствия

До замены и проверки реквизитов отправка заявок не считается готовой к выпуску. Тесты используют подставной транспорт, а владелец отдельно подтверждает доставку после локальной настройки; значения не появляются в документации, браузере и ответах API.
